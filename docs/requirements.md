# 要件定義（合意済みのドラフト）

## 目的
移動中に、スマホの内蔵 GNSS が今つかんでいる衛星とその受信状態をリアルタイムに見る。

## 前提・方針
- **Android のネイティブアプリ**（Kotlin / Jetpack Compose）。配布は **APK のみ**
- iPhone は対象外（OS が衛星ごとの情報を出さない）。**Google Play での公開も対象外**
- Play ストアを通さないため、インストール時に「提供元不明のアプリ」の許可が必要

## データ
- 内蔵 GNSS から **1 秒ごと** に取得する（外付けの受信機は使わない）
  - 衛星ごと: 測位系、衛星番号（SVID）、受信強度（C/N0）、方位、仰角、位置計算に使っているか
  - 位置: 緯度、経度、精度、測位状態（未測位 / 2D / 3D）
- 位置データは端末内だけで処理し、外部には送らない

## 画面・機能
- **スカイプロット**: 北を上にした円に、各衛星の方角と高さを点で表示
- **衛星一覧**: 測位系（GPS / みちびき / GLONASS / Galileo / BeiDou など）、SVID、C/N0、方位、仰角、使用の有無
- **受信強度の棒グラフ**
- **現在地と測位状態**: 緯度・経度・精度・未測位 / 2D / 3D、使用 / 捕捉の衛星数
- **地図と移動の軌跡**: OpenStreetMap（オフラインで使える形）。軌跡は捕捉している衛星数で色分け
- **バックグラウンド記録**: 画面を消していても、通知を出したまま記録を続ける。CSV / GPX で書き出す
- 見た目は Sony nav-u / Panasonic ストラーダの測位情報画面のようなカーナビ風（暗い背景、緑 = 使用 / 青 = 捕捉 / 灰 = 弱い）
  - 画面ラフ: https://cursor.com/canvas/store-6b8df988-9d93-4e08-80bf-9b57d543e5ff/32fc77e4-3355-45ae-becf-fe84d10a0c34

## v0.3 の詳細（地図・記録）
- 地図: osmdroid + OpenStreetMap 標準タイル。北が上で固定、現在地への追従と夜（反転）/ 昼の切り替え
  - タイル利用ポリシーに従い、識別できる User-Agent を送り、同時ダウンロードは 2 本まで。範囲の一括ダウンロードはしない
  - 一度表示したタイルは端末内にキャッシュ（最大 300MB）し、その範囲はオフラインでも表示する
  - 帰属表示「© OpenStreetMap contributors」を常に表示
- 軌跡: 使用衛星数で色分け（8 以上=緑、5〜7=黄、4 以下=橙）。5 秒以上の空白は点線
- 記録: フォアグラウンドサービス（`foregroundServiceType="location"`、`FOREGROUND_SERVICE_LOCATION`）。記録中は通知を表示し、通知から停止できる。Android 13 以降は `POST_NOTIFICATIONS` を記録開始時に求める
  - 記録はアプリが前面にあるときにボタンで開始する（バックグラウンド位置情報の権限は求めない）
  - 1 秒ごとの測位のうち、測位済み・新しい時刻の点だけを記録: 時刻、緯度、経度、高度、精度、速度、使用 / 捕捉衛星数
  - 記録はアプリ専用領域に 1 点ずつ追記し、最後の 1 回分を保持（次の記録開始で上書き）
- 書き出し: Storage Access Framework（保存先をユーザーが選ぶ）で CSV と GPX 1.1

## v0.5 の要件（多周波の内訳・精度の可視化・平均 C/N0）

v0.4.1 までの見た目と機能を維持したまま、**今の測位がどの帯域・測位系で成り立っているか**と、**精度を円と数値で見やすくする**ことを足す。実装・リリースは、この要件の合意後に別コミットで行う（この節は定義だけ）。

### いま取れているデータ（実装済み、v0.4.1）

1 秒ごとのスナップショット（`GnssUiState`）には、すでに次が入っている。v0.5 の集計のほとんどは、これを加工するだけで足りる。

- **衛星ごと**（`GnssStatus`、すでに取得）: 測位系、SVID、C/N0、方位、仰角、測位に使用中か、搬送波周波数 Hz（Android 8 / API 26 以上で `hasCarrierFrequencyHz` が真のときだけ。未対応の端末・OS では null）
- **位置**（`Location`、GPS プロバイダ）: 緯度、経度、水平精度 m（`hasAccuracy` / `getAccuracy`）、高度、測位時刻、速度、方位
- **まだ取っていない位置の値**: 垂直精度（`hasVerticalAccuracy` / `getVerticalAccuracyMeters`）、速度精度（`hasSpeedAccuracy` / `getSpeedAccuracyMetersPerSecond`）。どちらも API 26 以上。リポジトリは読んでいない
- **帯域のラベル**（`bandLabel`）: 周波数だけで `L1`（1550–1620 MHz）/ `L5`（1160–1195）/ `L2`（1195–1270）/ それ以外は `-`。Galileo の E5a（1176.45 MHz）も BeiDou の B2a も、今は全部「L5」と出る。E5b / B2I（1207 MHz）は「L2」に紛れる
- **記録**（`LogPoint` / CSV / GPX）: 時刻、緯度、経度、高度、水平精度、速度、使用衛星数、捕捉衛星数。帯域の内訳・デュアル周波数・垂直精度・平均 C/N0 はまだ無い
- **地図**: 現在地に水平精度の円を 1 つ描いている（`PositionOverlay`）。軌跡の色は使用衛星数（8 以上=緑、5–7=黄、4 以下=橙）

電離層遅延やマルチパスの指標は、端末によって `GnssMeasurements` から部分的に取れることもあるが、欠ける・信用できないことが多いので **対象外**（合意済み）。誤差楕円も Android が出さない（水平は半径 1 つのみ）ので **対象外**。

### A. 多周波（L1+L5）と測位系の内訳

#### 帯域の分け方と表示名

カウント用には、近い周波数を **帯域族** にまとめる（デュアル周波数の判定もこの族を使う）。表示名は、同じ周波数でも測位系に合わせて変える。

| 帯域族 | 周波数の目安（MHz） | 表示名の例 |
| --- | --- | --- |
| L1 | 1550–1620 | GPS / みちびき / SBAS: L1。Galileo: E1。BeiDou: B1C（1575 付近）または B1I（1561 付近）。GLONASS: G1 |
| L5 | 1164–1194 | GPS / みちびき / NavIC / SBAS: L5。Galileo: E5a。BeiDou: B2a（いずれも 1176.45 付近） |
| E5b | 1195–1217 | Galileo: E5b。BeiDou: B2I / B2b（1207 付近。周波数だけでは B2I と B2b を区別できないので `B2`） |
| L2 | 1218–1237 | GPS / みちびき: L2 |
| G2 | 1238–1258 | GLONASS: G2 |
| B3 | 1259–1272 | BeiDou: B3 |
| E6 | 1273–1290 | Galileo: E6。みちびき: L6 |
| 不明 | 周波数なし、または上以外 | `---`（カウントの「不明」） |

- `bandLabel(周波数)` に加え、`bandLabel(測位系, 周波数)`（表示用）と `bandFamily(周波数)`（集計・判定用）を用意する
- 既存のテスト（`bandLabel(1176.45e6) == "L5"` など）は、引数が周波数だけのときは **帯域族の名前**（L1 / L5 / L2 / E5b / G2 / B3 / E6）を返す、と読み替える。衛星一覧や詳細の 1 行は表示名（E5a / B2a など）を出す
- 周波数が無い端末では、帯域の内訳とデュアル周波数は出さない（`---`）。衛星の機数（使用 / 捕捉）と平均 C/N0 は従来どおり出す

#### カウントの定義

いずれも「衛星」（測位系 + SVID）単位。同じ衛星の L1 と L5 は、帯域ごとの数では両方に入る。

- **帯域ごとの捕捉 / 使用**: その帯域族の信号がある衛星の数、そのうち `usedInFix` の信号がある数。例: `L1 8 / 12`、`L5 5 / 7`
- **測位系ごとの捕捉 / 使用**: その測位系の衛星数（周波数では増やさない。今の `usedCount` / `capturedCount` と同じ数え方）
- **測位系ごとの平均 C/N0**: その測位系で **使用中の衛星**について、衛星ごとに最も強い信号の C/N0 を平均する（L1 と L5 を 2 回足さない）。使用中が 0 機なら `---`
- **デュアル周波数の衛星**: 同じ衛星で、L1 族と L5 族の信号がどちらも `usedInFix`。E1+E5a、B1C+B2a、L1+L5 はすべてこれに含める（L1+L2 や E1+E5b だけは、このフラグの対象外。数は帯域の内訳で見える）

#### 「デュアル周波数」表示の条件（推奨案）

**使用中のデュアル周波数衛星が 2 機以上**のとき「デュアル周波数」を点灯する。1 機だけでは点灯しない（たまたま 1 機だけ双周波で使われている状態と、測位が双周波で支えられている状態を分けたいため）。周波数が取れない端末、または条件を満たさないときは消灯（または `---`）。

このしきい値 `N=2` は下記「決めたいこと」の 1 番。合意前の既定値とする。

### B. 精度の可視化（円と数値のみ）

Android の `Location.getAccuracy()` は、**その位置を中心にした円の半径で、真の位置が円内に入る確率が約 68%** と定義されている。共分散や誤差楕円は来ない。

- **水平精度 (68%)**: いまの「精度 ±Xm」を、ラベルを「水平精度 (68%)」にして残す。値の意味を画面上でも短く示す
- **水平精度 (95%)（目安）**: 68% の半径に係数を掛けた円・数値。**2 次元・等方の正規分布（レイリー分布）を仮定**すると、68% 半径と 95% 半径の比は

  sqrt(-2 ln 0.05) / sqrt(-2 ln 0.32) ≈ 2.448 / 1.510 ≈ 1.62

  **掛け算は 1.62 倍を既定とする**（目安であり、実際の誤差分布はこれどおりではない）。よく見かける「2.45 倍」は、1σ（軸方向）から 95% 円を出す係数で、Android の「すでに 68% の半径」に掛けると円が過大になる。画面には「目安」と係数を一言添える（例: 「95% 目安（×1.62）」）
- **垂直精度**: API 26 以上で `hasVerticalAccuracy()` のときだけ表示（m）。無ければ `---`
- **速度精度**: API 26 以上で `hasSpeedAccuracy()` のときだけ表示（m/s を km/h に換算）。無ければ `---`
- **誤差楕円は出さない**
- **精度の履歴**: アプリ（UI）が動いているあいだ、直近 **60 秒**（1 秒 1 点）の水平精度 (68%) をメモリにだけ残し、小さな折れ線（スパークライン）で出す。アプリを終了したら捨てる（記録中の永続化は CSV / GPX 側）。値が無い区間は線を切る
- **地図の円**: いまの 68% の円に加え、95% 目安の円を破線で重ねる。半径が極端に大きいときは地図を埋め尽くさないよう描画を抑える（例: 画面を大きくはみ出す半径は輪郭だけ）
- **軌跡の色の切替（任意）**: 既定は今どおり使用衛星数。地図上の切替で「精度」にもできる。精度モードの目安: 水平精度 (68%) が 5 m 未満=緑、5–15 m=黄、15 m 超または値なし=橙。選択は端末に保存する（表示モードと同じ）

この係数と、軌跡の既定色は下記「決めたいこと」の 2・3 番。

### C. 使用衛星の平均 C/N0

測位に使っている衛星について、衛星ごとに最も強い信号の C/N0 を平均し、**常に**出す（測位前・使用 0 機は `---`）。単位は dB-Hz、小数 1 桁。帯域や測位系で割らない「全体の一口指標」。A の測位系ごとの平均とは別に持つ。

### 画面への出し方（nav-u 風のまま）

配色・タイトル帯・角丸パネル・昼夜は v0.4.1 を維持する。新しい数字も液晶風の等幅・右寄せ。値が無い項目は `---`。

**測位状況（測位情報）** — 主な置き場。

- 情報パネルに足す: **平均 C/N0**、**デュアル周波数**（点灯 / `---`）、水平精度を (68%) と 95% 目安の 2 行（または 1 行に併記）、垂直精度・速度精度（取れたときだけ行を出すか、常に行を置いて `---`）
- 帯域の内訳（L1 / L5 など、使用 / 捕捉）と、測位系ごとの貢献（機数と平均 C/N0）は、情報パネルの下か横の **小さな内訳パネル** にまとめる。左の「GPS Level」は受信強度の凡例のまま変えない
- 精度の履歴は、情報パネル内かその直下の **細いスパークライン**（高さは小さく、スカイプロットを圧迫しすぎない）
- **折りたたみ（Pixel Fold 外画面・縦）**: いまと同様、高さがあればスクロールなしで「高度・精度の行と下のボタンが重ならない」こと（`LayoutInsetsTest` を更新して維持）。足りない分はスカイプロットと棒グラフを少し縮め、内訳は 1 行のチップ（例: `L1 8/12  L5 5/7  双周波 3`）とスパークラインで収める。どうしても足りない低い画面だけ、従来どおりスクロール
- **展開（横）**: 左 = GPS Level、中央 = スカイプロット、右 = 情報パネル + 内訳 + スパークライン。棒グラフは下

**衛星一覧（衛星情報）**

- ヘッダーに、全体の平均 C/N0、デュアル周波数、帯域ごとの使用 / 捕捉を足す
- 「帯域」列は表示名（E5a / B2a など）。デュアル周波数の衛星は行に小さな印
- 測位系ごとの機数・平均 C/N0 はヘッダーの下の 1 行まとめでもよい

**地図（現在地マップ）**

- 68% の円 + 95% 目安の破線円
- 左上の状態ボックスに水平精度 (68%)、スペースがあれば 95% 目安・垂直精度
- 軌跡の色を「衛星数 / 精度」で切り替えるボタン（凡例も切り替える）
- 速度の表示は今どおり。速度精度は取れたときだけ添える

昼夜どちらでも、新しい文字・線・円のコントラストを既存の配色テストに足す。

### 記録（CSV / GPX）

`LogPoint` に任意項目を足し、記録開始から書く。

- 追加する値: 垂直精度 m、速度精度 m/s、使用衛星の平均 C/N0、デュアル周波数か（0/1）、デュアル周波数の使用機数、帯域族ごとの使用機数（少なくとも L1 と L5。他の族は値が 0 でなければ書く）
- **CSV**: 既存 8 列の **後ろに列を足す**（ヘッダーを更新）。古い 8 列だけのファイルも今までどおり読めること
- **GPX**: 名前空間は今の `gm:` のまま、任意の拡張要素を足す（例: `gm:verticalAccuracy`、`gm:speedAccuracy`、`gm:avgCn0`、`gm:dualFreq`、`gm:satsL1`、`gm:satsL5`）。古いファイルの読み込みは対象外（いま読んでいるのは CSV の再開用）
- 水平精度の 95% 目安は記録しない（係数を掛けた派生値なので、68% の半径から後で出せる）

### Android の制約（受け入れ時の前提）

- **minSdk 24** のまま。周波数・垂直精度・速度精度は **API 26 未満では常に無い**。無いときは `---` で落ちない
- 搬送波周波数も、API 26 以上でも `hasCarrierFrequencyHz` が偽なら null（機種・ドライバ依存）
- 水平精度は OS の推定で、68% とは限らない現場もある。95% 円は仮定付きの目安、と表示する
- 2D / 3D の判定は今どおり「使用衛星が 3 機なら 2D、4 機以上なら 3D」（高度の有無では決めない）
- 対象外: 誤差楕円、電離層・マルチパス指標、外付け受信機、軌道予測、過去ログの分析画面、minSdk の引き上げ

### 受け入れ条件とテスト

実装時に、少なくとも次を自動テストする（既存の 83 件は維持または意図した更新）。

- 帯域族と表示名: 1176.45 MHz は族 L5。GPS なら表示 `L5`、Galileo なら `E5a`、BeiDou なら `B2a`。1575.42 は GPS=`L1` / Galileo=`E1` / BeiDou=`B1C`。1561 は `B1I`。1207 は族 E5b（Galileo=`E5b`、BeiDou=`B2`）。1227.6 は `L2`（L2 に E5b を混ぜない）。null / NaN は空または `---`
- 帯域・測位系のカウント: 多周波の同一衛星は、衛星数では 1 機、L1 と L5 の使用数では両方に入る
- 平均 C/N0: 使用中だけ、衛星ごとに最大 C/N0 を平均。使用 0 機は null。L1+L5 の 1 機を 2 回平均しない
- デュアル周波数: L1 族と L5 族がともに使用中の衛星だけを数える。N=2 で点灯、1 機では消灯、0 機では消灯。E1+E5a は対象、L1+L2 だけは対象外
- 95% 半径: `horizontalAccuracy95(r68) = r68 * 1.62`（係数は 1 か所に置く）。null は null
- 記録: 新列付き CSV の書き出しと読み戻し。旧 8 列 CSV も読める。GPX に新拡張が付く
- UI: 測位状況に平均 C/N0・デュアル周波数・水平精度 (68%) が出る。未測位では `---`。`LayoutInsetsTest` の折りたたみ / 展開（411×700、841×650、673×841、短い画面のスクロール）が通る
- 配色: 昼夜で新しいラベルと 95% 円の線が読めること

手動（Pixel Fold）: 屋外で L5 系が見えること（または見えないときは `---` になること）、デュアル周波数の点灯、地図の二重の円、軌跡色の切替、折りたたみでも情報とボタンが重ならないこと。

### 決めたいこと（既定を先に置いてある）

実装に入る前に、次だけ確認する（既定のままでよければその旨だけでよい）。

1. **デュアル周波数を点灯する機数 N**: 既定は **使用中の L1 族+L5 族が 2 機以上**。1 機で点灯すると敏感、4 機だと街中ではほとんど点かない、という見積もり
2. **95% 円の係数**: 既定は **68% 半径の 1.62 倍**（2 次元正規分布の仮定）。2.45 倍にはしない（理由は上記）
3. **軌跡の色の既定**: 既定は **今どおり使用衛星数**。精度による色は切替で使う
