# GNSS モニター (gnss-monitor)

移動中に、スマホの内蔵 GNSS（GPS・みちびき・GLONASS・Galileo・BeiDou など）が **今どの衛星をつかんでいるか** を見るための Android アプリです。カーナビ（Sony nav-u / Panasonic ストラーダ）の「測位情報」画面のような、暗い背景の見た目を目指しています。

- Android 専用のネイティブアプリ（Kotlin + Jetpack Compose）
- 配布は APK のみ（Google Play では公開しません）
- 要件は [docs/requirements.md](docs/requirements.md)、画面ラフは [こちら](https://cursor.com/canvas/store-6b8df988-9d93-4e08-80bf-9b57d543e5ff/32fc77e4-3355-45ae-becf-fe84d10a0c34)

## 見た目（nav-u 風）

Sony nav-u の説明書にある「測位情報」画面（横向き・夜の見た目）に合わせています。ロゴや商標は使わず、配置・配色・質感だけを真似ています。

- **タイトル帯**: えんじ色（暗い赤紫）の無地の帯に白い文字「測位情報」。右端に GPS の受信レベルのランプ（赤 = 測位中 / 橙 = 捕捉中 / 灰 = 未受信）。画面ごとの名前は「測位情報」「衛星情報」「現在地マップ」
- **測位状況の並び**: 左に角丸の暗いパネル「**GPS Level**」、中央に正方形のスカイプロット、右に角丸の暗い情報パネル（横幅が足りない縦長の画面では、凡例とスカイプロットを上に、情報パネルを 2 列にして下に置く）
  - **GPS Level**: 球の色 = 受信の強さ。橙 + 棒 3 本 = 強い（C/N0 35 dB-Hz 以上）、黄緑 + 棒 2 本 = 中（25 以上）、灰 + 棒 1 本 = 弱い。その下に、測位系の頭文字の目印（G=GPS、J=みちびき、R=GLONASS、E=Galileo、C=BeiDou）と、「うすい球 = 測位に使っていない衛星」の説明
  - **スカイプロット**: 中心が暗く縁が紫の放射グラデーションの文字盤、細い白い外周、仰角リング 2 本（30° / 60°）、白い十字線、上に大きな白い「N」だけ（北が上）。衛星は光沢のある 3D の球で、中に SVID（暗い文字）。球の右上に測位系の頭文字の小さな丸。測位に使っていない衛星は薄く表示。球や棒をタップすると詳細（測位系・方位・仰角・周波数ごとの C/N0・使用/未使用）
  - **情報パネル**: 日付 `2026/11/27`、時刻 `10:59:08 AM`、緯度 `N 35°40'52"`、経度 `E 139°46'2"`、**速度**、高度、測位（未測位 / 2D / 3D）。続けてこのアプリの追加項目として衛星数（使用 / 捕捉）と水平精度。大きな白い等幅の文字で右寄せ。測位できていないときは `---`
  - **受信強度バー**: 衛星ごとに 1 本。色は球と同じ強さの 3 色（未使用は薄く）、下に測位系の頭文字と SVID
- **速度**: Android の `Location.speed`（m/s）を km/h（整数）で表示。速度が取れていない・測位前は `---`。地図の左下にも表示
- **下部ツールバー**: 控えめな濃いグレーの角丸ボタン（青い光沢はやめました）。選択中の画面だけえんじ色。「表示 自動 / 昼 / 夜」（自動は端末のダークテーマに従う。選択は端末に保存）と、右端の「← 戻る」（測位状況以外で押すと測位状況へ。端末の戻る操作も同じ）
- **衛星一覧・地図**: タイトル帯、パネル、ボタン、バーの色を同じ配色に統一。衛星一覧のバーも球と同じ 3 色、見出し帯はえんじ色。地図の重ね表示は暗い角丸パネル
- **昼テーマ**: 同じ構成で、背景とパネルだけ明るく（タイトル帯のえんじと文字盤の紫は共通）。地図は昼は通常の地図、夜は反転した暗い地図
- 昼夜どちらも文字が読めること、タイトル帯がえんじ色であること、ボタンが青くないこと、球の色の意味づけは、配色のテストで確認しています

## 多周波と精度（v0.5）

- **帯域の名前**: 搬送波周波数（Android 8 以上で、端末が返したときだけ）から決めます。1176 MHz は GPS / みちびきなら `L5`、Galileo なら `E5a`、BeiDou なら `B2a`。1575 MHz は `L1` / `E1` / `B1C`（1561 MHz の BeiDou は `B1I`）。1207 MHz は `E5b`（BeiDou は `B2`）、1227 MHz は `L2`、GLONASS は `G1` / `G2`。周波数が取れない端末では `---`（落ちません）
- **帯域の内訳**: 衛星（測位系 + SVID）単位で、帯域ごとの「使用 / 捕捉」を `L1 10/13  L5 6/6` のように出します。同じ衛星の L1 と L5 は、衛星数では 1 機、帯域の数では両方に入ります
- **デュアル周波数**: 同じ衛星の **L1 族と L5 族の信号がどちらも測位に使われている** 衛星が **2 機以上** のとき点灯します（E1 + E5a、B1C + B2a も対象。L1 + L2 だけは対象外）。1 機では点灯しません
- **平均 C/N0**: 測位に使っている衛星について、衛星ごとに最も強い信号の C/N0 を平均します（L1 と L5 を 2 回足さない）。測位前・使用 0 機は `---`。測位系ごとの平均は、受信強度バーの下の行（頭文字 + 使用/捕捉 + 平均）に出ます
- **水平精度**: Android の `Location.getAccuracy()` は「真の位置がこの半径の円に入る確率が約 68%」です。画面では **水平精度 (68%)**。**95% の円は目安**で、2 次元の正規分布を仮定して **68% の半径 × 1.62**（= 2.448 ÷ 1.510）で出しています。実際の誤差の分布はこのとおりとは限りません。誤差楕円は Android から来ないので出していません
- **垂直精度・速度精度**: Android 8（API 26）以上で端末が返したときだけ表示します（無いときは `---`）。速度精度は km/h に換算
- **精度の履歴**: 直近 60 秒の水平精度 (68%) の細い折れ線（メモリ上だけ。アプリの GNSS を止めると消えます）
- **地図**: 現在地に 68% の円（塗り + 実線）と 95% の目安の円（破線）。半径が画面を大きくはみ出すときは輪郭だけ・描かない。右上の「色: 衛星数 / 精度」で軌跡の色を切り替え（選択は端末に保存。既定は使用衛星数。精度モードは 5 m 未満 = 緑、5〜15 m = 黄、15 m 超または値なし = 橙）

## 記録と書き出し（v0.3、v0.5 で項目を追加）

1. 下の「地図」を開き、「● 記録開始」を押す（初回は通知の許可を求められます。許可すると記録中の通知が出ます）
2. 画面を消したり他のアプリに切り替えても、通知を出したまま 1 秒ごとに記録を続けます。通知の「記録停止」か、地図画面の「■ 記録停止」で止めます
3. 「CSV」「GPX」を押すと保存先を選ぶ画面が開くので、ファイル名と場所を決めて保存します（Google ドライブなども選べます）

- 記録する項目: 時刻（UTC）、緯度、経度、高度、精度、速度、使用衛星数、捕捉衛星数
- CSV の列（前半の 8 列は v0.3 から同じ）: `time_utc,latitude,longitude,altitude_m,accuracy_m,speed_mps,satellites_used,satellites_visible`
- v0.5 で後ろに追加した 8 列: `vertical_accuracy_m,speed_accuracy_mps,avg_cn0_dbhz,dual_freq,dual_freq_sats,sats_l1,sats_l5,sats_other_bands`（`sats_other_bands` は `L2:2;E5b:1` のように、L1 / L5 以外で使用数が 0 でない帯域。取れない値は空欄。古い 8 列だけの CSV も読めます。95% の目安は 68% の値から計算できるので記録しません）
- GPX 1.1: `ele` `time` `fix` `sat` に加え、速度・精度・捕捉衛星数を拡張要素（`gm:speed` `gm:accuracy` `gm:satsVisible`）に入れます。v0.5 では `gm:verticalAccuracy` `gm:speedAccuracy` `gm:avgCn0` `gm:dualFreq` `gm:dualFreqSats` `gm:satsL1` `gm:satsL5` `gm:satsOtherBands` も（値があるときだけ）付きます
- アプリ内に残るのは **最後の 1 回分の記録だけ** です（アプリを閉じても残り、次に記録を始めると上書き）
- 記録は位置情報の権限が「アプリの使用中のみ許可」で動きます（記録はアプリが前面にあるときにボタンで始めるため）

## 地図について

- 地図は [OpenStreetMap](https://www.openstreetmap.org/copyright) のタイルを [osmdroid](https://github.com/osmdroid/osmdroid) で表示します（© OpenStreetMap contributors）
- [タイル利用ポリシー](https://operations.osmfoundation.org/policies/tiles/) に沿って、アプリを識別できる User-Agent（`GNSSMonitor/バージョン (+https://github.com/mashishiii/gnss-monitor)`）を送り、同時ダウンロードは 2 本までにしています
- **一度表示したタイルだけ** を端末内（最大 300MB）にキャッシュし、電波が無いときもその範囲は表示できます。まだ表示したことのない範囲はオフラインでは出ません（範囲の一括ダウンロードは規約上行いません）
- 地図の色（夜は反転した暗い地図 / 昼は通常）は、下の「表示」ボタン（自動 / 昼 / 夜）に連動します。「追従中 / 現在地」ボタンで現在地への追従に戻ります。地図を指で動かすと追従は解除されます

## 向きと動き（v0.6）

- **ノースアップ / ヘディングアップ**: 地図の右上の方位バッジ（赤い針と「N」が真北を指す）をタップするか、測位状況のスカイプロットの外周にある「N」をタップで切り替えます。**設定は 1 つだけ**で、地図とスカイプロットに共通です（端末に保存。初回はヘディングアップ）
- **進行方向**: GNSS の対地コース（`Location.bearing`）。速度が 1 m/s（約 3.6 km/h）以上のときだけ更新し、それより遅いと直前の向きを保ちます。電子コンパスは使いません。一度も向きが取れていない間（起動直後・停止中）は、ヘディングアップでも北が上のままで、スカイプロットの左上に小さく「方位なし」と出ます
- **地図**: ヘディングアップでは進行方向が上になるよう地図が回り、追従中は現在地を中央より下（下から約 35%）に置いて前方を広く見せます。指で動かすと追従が外れ、その瞬間の向きのまま、現在地も中央に戻ります。「現在地」ボタンで追従に戻ると、保存した向きに戻ります。2 本指の回転はありません。ラスタータイルの地名は地図と一緒に回るので、南向きでは逆さになります（OSM タイルの限界）
- **スカイプロット**: ノースアップは今までどおり上に「N」だけ。ヘディングアップでは文字盤が回り、「N」が真北の外周へ、E / S / W も出ます（文字は直立）。衛星の球は `方位 − 進行方向` で回り、十字線とリングは動きません。衛星一覧と詳細の方位・仰角は常に真北基準です
- **動き: レトロ / スムーズ**（地図の右上のボタン、保存、既定はレトロ）: レトロは 1 秒ごとに地図・現在地・向きがパッと切り替わる当時の動き（補間なし）。スムーズは次の測位まで約 1 秒かけて補間します。地図の移動・回転・現在地マーカーとスカイプロットの回転にだけ効き、受信強度バーや数値・衛星の方位 / 仰角には効きません

## インストール方法（APK）

1. このリポジトリの [Releases](https://github.com/mashishiii/gnss-monitor/releases) を Android のスマホで開く
2. 最新バージョンの `gnss-monitor-vX.Y.Z.apk` をダウンロードする
3. ダウンロードした APK を開く。「この提供元のアプリを許可」のような画面が出たら、ブラウザ（または使っているファイル管理アプリ）に **「提供元不明のアプリ」のインストールを許可** してインストールする
4. 初回起動時に位置情報の許可（ACCESS_FINE_LOCATION）を求められるので許可する。屋外で空が開けた場所のほうが衛星を多くつかめます

> Play ストアを通さない APK のため、インストール時に上記の許可が必要です。インストール後は許可を戻して構いません。

## 位置情報について

位置情報や衛星のデータは端末の中だけで処理し、外部のサーバーには送りません。将来の記録機能で書き出す CSV / GPX などの **位置情報のログは、リポジトリにコミットしません**（`.gitignore` で `*.csv` `*.gpx` `logs/` を除外しています）。署名用の鍵（`*.jks` `*.keystore`）も同様です。

## 開発

必要なもの: JDK 17、Android SDK（compileSdk 37.1）。

```sh
./gradlew testDebugUnitTest assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
```

- `main` への push と PR で CI（[.github/workflows/ci.yml](.github/workflows/ci.yml)）がテストとデバッグ APK のビルドを実行します
- `v0.1.0` のようなタグを push すると、[release.yml](.github/workflows/release.yml) が署名付き APK をビルドし、GitHub Releases に公開します
  - 署名には Secrets の `KEYSTORE_BASE64` `KEYSTORE_PASSWORD` `KEY_ALIAS` `KEY_PASSWORD` を使います（ローカルでは環境変数 `KEYSTORE_FILE` なども同じ名前。未設定なら未署名でビルドされます）
  - バージョン名はタグから、バージョンコードは Actions の実行番号から自動で決まります
